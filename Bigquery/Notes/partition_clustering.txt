Bigquery Partitions:
    - It is a technique to devide the large table into smaller segments based on specific columns.
    - It is to avoid complete scan of table.
    - Avoid partitioning the table with column have more unique data.

Types:
1. Integer based Partitions
    Partition the table based on the integer value columns with range.
    Ex: A customer table is partitioned by 'customer_id' (1-10000,10001-20000..)
    SQL:
        CREATE TABLE mydataset.newtable (customer_id INT64, date1 DATE)
        PARTITION BY
        RANGE_BUCKET(customer_id, GENERATE_ARRAY(0, 100, 10))
        OPTIONS (
            require_partition_filter = TRUE);

2. Ingestion based partition:
    Partition the table based on ingestion time.
    It automatically parition the table with '_PARTITIONTIME'
    Ex: When data is migrated on day basis.
    SQL:
        CREATE TABLE
        mydataset.newtable (transaction_id INT64)
        PARTITION BY
        _PARTITIONDATE
        OPTIONS (
            partition_expiration_days = 3,
            require_partition_filter = TRUE);

3. Time based partition:
    Partition the table based on DATE, DATETIME, TIMESTAMP
    Ex: Orders table is partitioned by 'order_date'
    SQL:
        CREATE TABLE
        mydataset.newtable (transaction_id INT64, transaction_date DATE)
        PARTITION BY
        transaction_date
        OPTIONS (
            partition_expiration_days = 3,
            require_partition_filter = TRUE);

Limitations:
1. A bigquery does not support multi column partitions. It can have only one column partition.
2. A single table can have 10000 partitions.

Metadata:
    INFORMATION_SCHEMA.PARTITIONS 
        - Table name, partition id and number of rows in partition id.

BIGQUERY CLUSTERING:
    - It is the technique to sort the data based on the clustered columns for faster retrivel.
    - It improves the query performance and reduce query cost.
    - Use clustering on column which is used frequently on filter condition.

Limitations:
    - A table can be clustered max four columns.
    - Altering non clustered table to clustered table wont automatically cluster the existing data of the table.
    - Avoid clustering if the column has more dublicates like 'gender' column.

Metadata:
    INFORMATION_SCHEMA.COLUMNS

CLUSTERING AND PARTITIONING:
    - A partitioned table can be clustered
    - Both Partitioning and clustering combined improves query performance and reduce cost.
    - In each partition the data is sorted based on clustered column.
